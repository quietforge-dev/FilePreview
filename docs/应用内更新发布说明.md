# 应用内更新发布说明

FilePreview 使用 Tauri updater 从 GitHub Release 下载、校验、安装并重启应用。客户端只读取固定的 `latest.json` 地址，不依赖 GitHub REST API。

## 首次配置

开发机的更新签名私钥保存于 `src-tauri/keys/updater.key`，该目录已被 Git 忽略。私钥必须妥善备份；丢失后，已安装版本无法验证未来更新。

在 GitHub 仓库的 `Settings -> Secrets and variables -> Actions` 新建 Repository secret：

| 名称 | 值 |
| --- | --- |
| `TAURI_SIGNING_PRIVATE_KEY` | `src-tauri/keys/updater.key` 的完整内容 |

当前私钥未设置密码，因此无需创建 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`。不要提交私钥、不要把私钥作为 Release 附件，也不要在 issue 或日志中输出。

## 发布结果

推送 `v*` tag 后，GitHub Actions 会构建 Windows x64 和 arm64 的安装包，并发布：

- `FilePreview-Windows-x64.exe` 和 `FilePreview-Windows-arm64.exe`
- 对应的 `.sig` 更新签名文件
- `latest.json` 更新清单

工作流在开始时检查 `TAURI_SIGNING_PRIVATE_KEY`。缺少该 Secret 时，tag 构建会失败，避免发布无法完成自动更新校验的版本。
