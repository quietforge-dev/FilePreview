# FilePreview 架构说明

## 前端

前端保持单向依赖：`api -> store -> page/component`。

- `src/api/`：唯一的 Tauri IPC 调用入口，不包含界面状态。
- `src/stores/`：跨组件状态和用例编排，例如工作区、会话标签、预览和搜索。
- `src/services/preview/`：格式渲染策略；格式判断只在 `canHandle` 中出现。
- `src/components/`：可复用展示与局部交互，不直接调用文件系统或 Tauri command。
- `src/pages/`：页面编排、路由级生命周期与跨领域用户动作。
- `src/types/`：IPC 与共享领域类型。

禁止页面直接调用 `invoke`、组件直接修改持久化数据，以及通过扩展名分支绕过预览器注册表。

## 后端

后端保持单向依赖：`commands -> service -> dao`。

- `commands/`：按 `app`、`workspace`、`history`、`session` 划分 Tauri command，只处理 IPC 参数、状态注入和错误映射。
- `service/`：工作区、历史、会话、Office 转换和文件监听等业务用例。
- `dao/`：只负责 SQLx 查询与事务，不包含工作区校验或 UI 逻辑。
- `model/`：按 `file`、`history`、`office`、`session` 划分 IPC 与持久化模型，并从 `model/mod.rs` 统一导出。
- `database/`、`config/`：数据库连接、migration 与用户数据目录配置。
- `filesystem.rs`：受工作区 service 调用的本地文件系统实现；所有外部路径先在 service 中规范化并做工作区边界校验。

新增持久化数据必须追加 `src-tauri/migrations/` migration；新功能优先增加对应 command、service、dao 和 model，不在页面或 command 中跨层实现业务逻辑。

## 仓库边界

- `src/` 和 `src-tauri/` 是产品代码。
- `scripts/` 是开发与发布入口。
- `docs/` 保存产品、架构和发布说明。
- `skills/` 与 `AGENTS.md` 保存项目协作规范。
- `dist/`、`node_modules/`、`src-tauri/target/`、`*.tsbuildinfo`、`build-output.log`、`remark.txt` 是生成物或本地记录，必须保持忽略。
- 项目没有 Python 运行时；根目录的 Python 示例不得作为产品入口保留。
